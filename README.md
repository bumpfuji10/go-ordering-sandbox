# go-ordering-sandbox

Go の学習用に作る、小さな飲食店向けの注文システム。

## 技術構成

| 領域 | 採用 |
|---|---|
| バックエンド | Go / 標準ライブラリ `net/http` |
| DB アクセス | `database/sql` + pgx |
| データベース | PostgreSQL 17 |
| フロントエンド | Vite + React + TypeScript |
| バージョン管理 | mise (Go 1.27.0 / Node 24.21.0) |

フレームワークを使わず標準ライブラリで組むのは、Go の基礎を理解することを目的としているため。

## 要件

### 想定する業態

小さな飲食店。お客様がテーブルに着席し、店員が注文を取り、食事を終えて会計する。

### 利用者

店員のみ。お客様が直接操作する端末や、厨房向けの画面は対象外。

### システムが記録する操作

実際の業務の流れのうち、記録が必要なのは次の 4 点に絞られる。

| # | 操作 | システムの動作 |
|---|---|---|
| 1 | 入店・案内 | 伝票を開く（テーブル番号を指定） |
| 2 | 注文 | 伝票に明細を追加する（何度でも） |
| 3 | 会計 | 合計を計算して会計済みにする |
| 4 | 退店 | 伝票を閉じる |

「メニューを見る」「店員を呼ぶ」「食べ終わる」といった行為は現実の世界で完結するため、
システムには記録しない。

### データ構造

注文は食事中に何度も発生するが、会計は退店時に一度だけ行われる。
注文の単位と会計の単位が異なるため、複数の注文をまとめる入れ物として「伝票」を置く。

```
伝票 (check)  1 ─ N  注文 (order)  1 ─ N  明細 (order_item)
```

### 業務ルール

- `open` の伝票にしか注文を追加できない
- `open` の伝票しか会計できない（二重会計の防止）
- 1 つのテーブルに `open` の伝票は同時に 1 つだけ
- 品切れのメニューは注文できない
- メニューの価格を変更しても、過去の伝票の金額は変わらない

価格の変更が過去に波及しないよう、明細には注文時点の品名と単価をコピーして保存する。

### 設計方針

- 合計金額はカラムとして保存せず、明細から計算する（冗長なデータを持たない）
- 金額の計算はドメイン層に置く。DB は明細を正確に保存して返すことに徹する
- 金額は円単位の整数で扱う（浮動小数点数は誤差が出るため使わない）

## ディレクトリ構成

```
backend/
  cmd/api/          エントリポイント
  internal/         アプリ内部の実装（外部から import できない）
    menu/           メニュー
    order/          注文
    db/             データベースへの接続
    env/            環境変数の読み取り
    httpx/          HTTP 共通処理
    server/         ルーティング
  db/
    migrations/     スキーマ定義
    seeds/          開発用データ
    init.sh         初回起動時に migrations → seeds の順で流し込む
frontend/           Vite + React
compose.yml         PostgreSQL
mise.toml           ツールのバージョンとタスク
```

Go ではレイヤー（model / controller）ではなく関心事（menu / order）でパッケージを分けるのが一般的なため、
それに従っている。

## 開発環境の起動

```bash
# ツールの用意
mise install

# データベース（初回はスキーマと開発用のメニューが自動で入る）
docker compose up -d --wait

# バックエンド（http://localhost:8080）
cd backend && go run ./cmd/api

# フロントエンド（/api への要求はバックエンドへ中継される）
cd frontend && npm install && npm run dev
```

### 環境変数

| 変数 | 既定値 | 用途 |
|---|---|---|
| `PORT` | `8080` | API サーバーの待ち受けポート |
| `DB_HOST` / `DB_PORT` | `localhost` / `5432` | 接続先 |
| `DB_USER` / `DB_PASSWORD` / `DB_NAME` | `app` / `password` / `ordering` | compose.yml の設定に合わせてある |
| `DB_SSLMODE` | `disable` | |
| `API_URL`（フロントエンド） | `http://localhost:8080` | Vite が `/api` を中継する先。`PORT` を変えたときに合わせる |

```bash
# 例: 8080 が埋まっているとき
PORT=8081 go run ./cmd/api
API_URL=http://localhost:8081 npm run dev
```

### データベースを作り直す

`migrations` と `seeds` が実行されるのは、データ領域が空のとき（ボリュームを初めて作ったとき）だけ。
スキーマや開発用データを変えたら、ボリュームごと作り直す。**保存したデータはすべて消える。**

```bash
mise run db:reset
```

### テスト

```bash
mise run test   # cd backend && go test ./... と同じ
```

## API

| メソッド | 経路 | 内容 |
|---|---|---|
| `GET` | `/healthz` | 死活監視 |
| `GET` | `/api/menu-items` | メニューの一覧。`category=food\|drink`、`availableOnly=true` で絞り込める |
| `GET` | `/api/menu-items/{id}` | メニュー 1 件。存在しなければ 404 |

エラーは状態コードとともに `{"error": "メッセージ"}` の形で返す。
